# 代码结构重新组织规范

## 目标

按照整洁架构（Clean Architecture）的要求，重新组织代码结构，将代码按照层次关系封装在不同的类库中，实现更清晰的职责划分和依赖关系。

## 架构层次

### 1. Core 层（核心层）

**职责**：包含领域模型、领域服务、共享接口和工具类，是整个应用的核心。

**文件结构**：
```
src/MinGo.Core/
├── Entities/              # 领域实体
├── Models/                # 领域模型
├── Interfaces/            # 领域接口
├── Services/              # 领域服务
├── Exceptions/            # 领域异常
└── Utils/                 # 共享工具类
```

### 2. Application 层（应用层）

**职责**：包含应用服务、业务逻辑、命令/查询处理等，负责协调领域对象完成业务功能。

**文件结构**：
```
src/MinGo.Application/
├── Services/              # 应用服务
├── Commands/              # 命令处理
├── Queries/               # 查询处理
├── DTOs/                  # 数据传输对象
└── Mappers/               # 对象映射
```

### 3. Infrastructure 层（基础设施层）

**职责**：包含数据访问、外部服务集成、配置等与外部系统交互的实现。

**文件结构**：
```
src/MinGo.Infrastructure/
├── Data/                  # 数据访问
├── Repositories/          # 仓库实现
├── ExternalServices/      # 外部服务集成
├── Configuration/         # 配置
└── Utils/                 # 基础设施工具类
```

### 4. Web 层（表现层）

**职责**：包含API控制器、Blazor组件、中间件等，负责与外部系统交互。

**文件结构**：
```
src/MinGo.Web/
├── Controllers/           # API控制器
├── Pages/                 # Blazor页面
├── Components/            # Blazor组件
├── Middlewares/           # 中间件
├── Services/              # Web层服务
└── Extensions/            # 扩展方法
```

### 5. Gateway 层（网关层）

**职责**：包含反向代理、路由配置等网关核心功能。

**文件结构**：
```
src/MinGo.Gateway/
├── Services/              # 网关服务
├── Extensions/            # 扩展方法
├── Options/               # 配置选项
└── Middlewares/           # 网关中间件
```

## 依赖关系

- **Core** 层：无依赖
- **Application** 层：依赖 Core 层
- **Infrastructure** 层：依赖 Core 层
- **Web** 层：依赖 Application 层和 Infrastructure 层
- **Gateway** 层：依赖 Core 层和 Infrastructure 层

## 代码迁移计划

### 1. Core 层迁移

- 将 `MinGo.Shared.Models` 中的领域模型迁移到 `MinGo.Core.Entities`
- 将 `MinGo.ControlPlane.Services.ServiceInterfaces` 中的接口迁移到 `MinGo.Core.Interfaces`
- 将共享工具类迁移到 `MinGo.Core.Utils`

### 2. Application 层迁移

- 将 `MinGo.ControlPlane.Services` 中的服务实现迁移到 `MinGo.Application.Services`
- 创建必要的命令/查询处理类
- 创建 DTO 类和映射器

### 3. Infrastructure 层迁移

- 将 `MinGo.Shared.Data` 中的数据访问代码迁移到 `MinGo.Infrastructure.Data`
- 将 `MinGo.Gateway.Services` 中的配置提供程序迁移到 `MinGo.Infrastructure.ExternalServices`
- 将数据库迁移文件迁移到 `MinGo.Infrastructure.Data.Migrations`

### 4. Web 层迁移

- 将 `MinGo.ControlPlane.Controllers` 迁移到 `MinGo.Web.Controllers`
- 将 `MinGo.ControlPlane.Pages` 迁移到 `MinGo.Web.Pages`
- 将 `MinGo.ControlPlane.Shared` 迁移到 `MinGo.Web.Components`

### 5. Gateway 层迁移

- 保留 `MinGo.Gateway` 作为独立项目
- 调整其依赖关系，使其依赖 Core 和 Infrastructure 层

## 项目引用关系

- `MinGo.Core`：无引用
- `MinGo.Application`：引用 `MinGo.Core`
- `MinGo.Infrastructure`：引用 `MinGo.Core`
- `MinGo.Web`：引用 `MinGo.Application`、`MinGo.Infrastructure`
- `MinGo.Gateway`：引用 `MinGo.Core`、`MinGo.Infrastructure`

## 实施步骤

1. 创建新的项目结构
2. 迁移 Core 层代码
3. 迁移 Application 层代码
4. 迁移 Infrastructure 层代码
5. 迁移 Web 层代码
6. 调整 Gateway 层依赖
7. 更新项目引用
8. 验证代码结构和功能

## 注意事项

- 保持代码的函数级注释
- 确保所有依赖关系正确配置
- 验证所有功能正常运行
- 保持代码风格一致
- 移除不必要的默认代码和实现
